# 開発の進め方

C# の構成、EF Core、トランザクションを扱う場合は [バックエンドの設計方針](references/backend-design.md) を読む。着手前の確認項目も同じ文書にある。

1. 既存の仕様、実装、テストを読み、正常系・異常系・互換性を含めて受入条件を決める。確認済み、仮定、未確定を区別し、設計やデータに影響する未確定事項から確認する。
2. 既存の機能仕様があればそこを更新する。新機能や複数レイヤーにまたがる仕様は、既存の文書構成に従い、置き場所がなければ `docs/<feature>/spec.md` に利用者から見える動作、入出力、失敗時の挙動、受入条件を書く。軽微な修正は既存の仕様やテストに反映する。
3. 選択肢で迷った設計判断だけ、理由を実装計画または PR に短く残す。既存構成を踏襲し、通常の起動・公開経路で機能する最小の変更を入れる。
4. API 契約や画面の API 呼び出しを触る場合は [update-api-client](../update-api-client/SKILL.md) を使う。検証には [verify-changes](../verify-changes/SKILL.md) を使う。
5. 起動、設定、生成、テスト、公開の手順が変わったら README を更新する。利用者の動作は機能仕様に、作業ルールは AGENTS.md または該当のスキルに置く。コマンドとリンクは実際のパスで確認する。
6. 受入条件ごとに確認済み・未達・未検証を整理する。未達は修正して再確認し、未検証は理由と範囲を報告する。
